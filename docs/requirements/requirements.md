## 1. 概要

### 1.1 背景

本アプリは学習課題として作成する。作成を通して、次の 4 つを習得する。

- ユーザー認証（登録・ログイン・ログアウト）と、ワークスペースごとの権限（オーナーとメンバー）
- データの作成・表示・更新・削除（CRUD）と、データどうしの関係（ワークスペース・チャンネル・メッセージ・スレッド・リアクション）
- リアルタイムの通信（WebSocket）：送ったメッセージを、画面を開き直さずにほかの人の画面に出す
- 画像・動画のアップロードと保存（AWS S3）

あわせて、AWS で公開する方法を身につける。技術は前に作った BookLog・Raise timeline と同じもの（Spring Boot・React・PostgreSQL）を使う。

メールや一般のメッセージアプリで仲間内のやり取りをすると、次の点で不便である。

- 話題ごとに場所を分けられず、いくつもの話が 1 つの流れに混ざる
- ある発言への返事が、ほかの話の間に埋もれる
- 前のやり取りを探しにくく、どこまで読んだか・自分あての話があるかがわかりにくい

### 1.2 目的

1. 仲間ごとにワークスペースを作り、その中を話題ごとのチャンネルに分けて、テキスト・画像・動画でやり取りできるようにする
2. 送ったメッセージが、相手の画面にすぐ（画面を開き直さずに）出るようにする
3. スレッドで返信し、リアクションとメンションで手軽に反応・呼びかけができるようにする
4. 未読とメンションを知らせ、前のメッセージを検索できるようにする
5. ワークスペースを作った人（オーナー）が、招待・キック・チャンネルの追加と削除で場を管理できるようにする

## 2. 範囲

### 2.1 対象範囲

開発は 1 回で行い、8 章の機能（FN-01〜FN-14）をすべて作ってから検収する。機能ごとの要件 ID は、機能定義書で付ける。

### 2.2 対象外（今回やらないこと）

| 項目 | 補足 |
| --- | --- |
| ボイスチャンネル（音声・ビデオ通話、画面共有） | 依頼の時点で対象外と決まっている |
| 3 人以上のダイレクトメッセージ、自分あてのダイレクトメッセージ | ダイレクトメッセージは同じワークスペースの 2 人の間だけ |
| @channel・@here、グループへのメンション | メンションできるのは 1 人ずつ |
| カスタム絵文字 | リアクションに使えるのは Unicode の絵文字だけ |
| スレッドの返信をチャンネルにも送ること | スレッドの返信はスレッドの中にだけ出す |
| ピン留め・ブックマーク・リマインダー・予約送信・メッセージの転送 | |
| 画像・動画以外のファイル（PDF・Office の文書・圧縮ファイルなど）の添付、ファイルの一覧画面 | |
| 動画の変換（圧縮・形式の変換・サムネイルの作成） | 送られたファイルのままブラウザで再生する。再生できる形式はデータ要件定義書 6.1 |
| チャンネルの名前の変更・アーカイブ、公開とプライベートの切り替え | 変えたいときは新しいチャンネルを作る |
| オーナー以外の管理者、オーナーの引き継ぎ | 管理の操作ができるのは、ワークスペースを作った 1 人だけ |
| 既読の人の表示（「既読 3」など）、入力中の表示 | |
| メールアドレスの登録・メール認証・パスワードの再発行 | パスワードを忘れた場合は作り直す |
| メールやスマートフォンのプッシュ通知 | 通知はアプリの画面の中で行う（FN-14、U-5） |
| ボット・Webhook など外部のサービスとの連携 | |
| スマートフォン用のアプリ | ブラウザで使う。スマートフォンのブラウザには対応する（3.2） |
| 英語など日本語以外の表示 | |
| 短い間の大量の操作の制限 | 利用者は数十人で、知っている人どうしで使うため |

## 3. 利用者と利用環境

### 3.1 利用者

| 項目 | 内容 |
| --- | --- |
| 利用者 | ユーザー登録した人。登録は誰でもできる |
| 想定する主な利用者 | 作成者本人、検収者、試しに使う人（合わせて数十人） |
| オーナー | ワークスペースを作った人。そのワークスペースで、招待リンクの作成と取り消し、メンバーのキック、チャンネルの削除ができる（FN-04・FN-05・FN-06）。ワークスペースごとに 1 人 |
| メンバー | 招待リンクからワークスペースに参加した人。オーナーもメンバーの 1 人として数える |
| 見られる範囲 | 自分が入っているワークスペースの中で、公開チャンネル（入っていなくても見られる）、自分が入っているプライベートチャンネル、自分のダイレクトメッセージ、メンバーのプロフィール。入っていないワークスペースのものは、名前も含めて何も見られない。ログインしていない人は何も見られない（招待リンクの画面のワークスペース名を除く） |
| 変えられる範囲 | 自分のメッセージ・添付・リアクション・プロフィールだけ。ほかの人のものは、オーナーでも変えられない（U-2）。ただし、オーナーがチャンネルを削除したときは、そのチャンネルのほかの人のメッセージもまとめて消える |

### 3.2 対応環境

検収の時点での各ブラウザの最新版で動作を保証する。

| OS | ブラウザ |
| --- | --- |
| Windows 11 | Google Chrome、Microsoft Edge、Mozilla Firefox |
| macOS 14 以降 | Safari、Google Chrome |
| iOS 17 以降 | Safari |
| Android 14 以降 | Google Chrome |

| 項目 | 条件 |
| --- | --- |
| 画面の横幅 | 375px〜1920px |
| 画面の拡大率（OS・ブラウザ） | 100%〜150% |
| インターネット接続 | 必須（下り 10Mbps 以上を想定） |

## 4. 前提条件・制約

| ID | 内容 |
| --- | --- |
| P-1 | データはリレーショナルデータベース（PostgreSQL）に保存する。開発中は Docker、公開時は AWS RDS で動かす。バージョンなどは技術スタック定義書に記録する |
| P-2 | 添付の画像・動画とアバター画像は AWS S3 に保存し、データベースには置き場所だけを持つ。開発中は S3 の開発用のバケットを使い、自動のテストでは S3 と同じ使い方ができる MinIO を Docker で動かす |
| P-3 | リアルタイムの通信は WebSocket で行う。画面は開いている間 API サーバーとつなぎ続け、新しいメッセージなどをサーバーから受け取る。切れたときは自動でつなぎ直し、切れていた間の分を取り直す |
| P-4 | 公開する場合は AWS に、CloudFront（入口・HTTPS）・ロードバランサー（ALB）・API のコンテナ（ECS Fargate）・データベース（RDS）・S3（画面と添付）で構築する。画面は S3 に置いて CloudFront から配る。公開の URL は CloudFront のもの（https://〜.cloudfront.net）とし、独自ドメインは取らない。API のコンテナは 1 つだけ動かす（複数にするとコンテナどうしでリアルタイムの通知を受け渡す仕組みが要るため）。構成はインフラ設計書に書く |
| P-5 | AWS は有料のため、公開は検収のときだけ行い、使わない間は API のコンテナと ALB を消し、RDS を止める。検収が終わったら環境を消す |
| P-6 | 利用者が使える機能・画面の動きは本書に書いたものに限る。本書に書いていない動きは保証しない |
| P-7 | 公開後の稼働状況は、AWS の稼働状況に左右される（11.2 参照） |

## 5. 用語

| 用語 | 意味 |
| --- | --- |
| ユーザー | アカウントを登録した人 |
| ユーザー ID | ログインとメンションに使う、ほかと重ならない英数字の名前。画面では @ を付けて出す（例：@taro_y） |
| 表示名 | メッセージに出す名前。ほかの人と同じでもよい（例：たろう） |
| アバター | プロフィールの画像。登録していない人は、表示名の頭文字を丸の中に出す |
| ステータス | プロフィールに付ける、いまの状態を表す絵文字 1 つと短い文（例：🏖 休暇中）。期限を決めて自動で消せる |
| ワークスペース | 仲間ごとの場。チャンネルとダイレクトメッセージはワークスペースの中にある。ワークスペースどうしのデータは混ざらない |
| オーナー | ワークスペースを作った人。管理の操作ができる（3.1） |
| メンバー | ワークスペースに入っている人。オーナーを含む |
| 招待リンク | オーナーが作る、ワークスペースに参加するための URL。開いてログインすると参加できる。期限があり、オーナーが取り消せる |
| キック | オーナーがメンバーをワークスペースから外すこと（強制退出） |
| チャンネル | ワークスペースの中の、話題ごとのメッセージの場。公開チャンネルとプライベートチャンネルがある |
| 公開チャンネル | ワークスペースのメンバーなら誰でも見られ、自分で参加できるチャンネル |
| プライベートチャンネル | そのチャンネルのメンバーに招待された人だけが見られ、参加できるチャンネル |
| general | ワークスペースを作ったときに自動でできる公開チャンネル。メンバー全員が入っていて、退出・削除できない |
| ダイレクトメッセージ（DM） | 同じワークスペースの 2 人だけのメッセージの場 |
| 会話 | チャンネルと DM をまとめた呼び方 |
| メッセージ | 会話に送る文章。画像・動画を添付できる。Markdown 記法で書ける |
| Markdown 記法 | 「`**太字**`」のように、記号で文字の飾りを指定する書き方。使える記法は機能定義書で定める |
| スレッド | あるメッセージ（親メッセージ）への返信をまとめたもの。返信は親メッセージの下にまとめて出し、会話の流れには出さない |
| リアクション | メッセージに付ける絵文字。1 人が 1 つのメッセージに、違う絵文字をいくつでも付けられる |
| メンション | メッセージの中で「@ユーザー ID」と書いて、その人に呼びかけること。された人に通知する |
| 未読 | 会話の中で、自分が最後に開いた後に届いたほかの人のメッセージ |
| 通知 | 未読があること、メンションされたことを画面に出して知らせること（FN-14） |
| サイドバー | チャット画面の左側の、ワークスペース名・チャンネルの一覧・DM の一覧を出す部分 |
| 署名付き URL | 一定時間だけ使える、S3 の画像・動画を表示するための URL。期限が切れると開けなくなる |
| JWT | ログインした人が誰かを表す、改ざんを見破れる署名つきの文字列（JSON Web Token）。本アプリでは、ログインの状態をサーバーに覚えさせずに、この文字列で確かめる |
| WebSocket | ブラウザとサーバーの間でつなぎ続け、サーバーからもいつでもデータを送れる通信の方式 |
| 確認ダイアログ | 操作を実行する前に「よろしいですか？」と確認する小さな画面 |
| トリム | 入力した文字の前後にある空白（半角・全角スペース、タブ、改行）を取り除くこと |
| 文字数 | Unicode の文字（コードポイント）の数。漢字・ひらがな・英数字は 1 文字。絵文字の一部（肌の色を変えたもの、国旗など）は、見た目は 1 文字でも 2 文字以上として数える |

## 6. 利用の流れ

1. ブラウザでアプリの URL を開く
2. 初めての場合は「アカウントを作る」からユーザー登録する。2 回目以降はユーザー ID とパスワードでログインする
3. ワークスペースの一覧が表示される。新しく始める人は「ワークスペースを作る」で作り、オーナーになる。友人から招待リンクをもらった人は、そのリンクを開いて参加する
4. ワークスペースを選ぶと、チャット画面が表示される。左のサイドバーからチャンネルか DM を選ぶ
5. オーナーは招待リンクを作って友人に渡し、必要なチャンネルを作る。メンバーも、公開チャンネル・プライベートチャンネルを作れる
6. メッセージを送る。画像・動画を添付したり、「@ユーザー ID」でメンションしたりする。ほかの人のメッセージにはリアクションを付けたり、スレッドで返信したりする
7. 未読やメンションがある会話は、サイドバーで太字と件数で知らせる。メンションは「メンション」の画面でまとめて見られる
8. 前のメッセージはヘッダーの検索欄で探す
9. 共用のパソコンで使った場合は、最後にログアウトする

## 7. 画面

画面は 18 個で、ログイン前の画面 2 つ（G-1・G-2）、ログイン後の画面 9 つ（G-3〜G-11。G-4 の招待の参加画面だけは、ログイン前にもワークスペースの名前を出す）、ダイアログ 7 つ（G-12〜G-18）からなる。中心となるのはチャット画面（G-5）で、サイドバー・メッセージの一覧・スレッドのパネルを 1 つの画面に並べる。

画面一覧・画面遷移・チャット画面のイメージは[画面一覧](screens.md)に書く。

## 8. 機能一覧

機能は次の 14 である。機能ごとの要件・処理・API・エラーは、それぞれの機能定義書（本書の承認の後に作る）に書く。

| 機能 ID | 機能 | 概要 | 主な画面 |
| --- | --- | --- | --- |
| FN-01 | ユーザー登録・ログイン | ユーザー ID とパスワードで登録・ログイン・ログアウトする（メール認証なし）。ログインの状態は JWT で持つ（JWT 認証）。5 回続けて失敗したら 15 分間ログインできない。ログインしていないと何も使えない | G-1、G-2 |
| FN-02 | プロフィール | アバター画像・表示名・ステータス（絵文字と文、消す時刻）を設定する。プロフィールはすべてのワークスペースで共通。同じワークスペースのメンバーのプロフィールを見られる | G-10、G-16 |
| FN-03 | ワークスペース | ワークスペースを作る（作った人がオーナーになり、general ができる）。自分が入っているワークスペースの一覧から選んで切り替える | G-3、G-12 |
| FN-04 | 招待 | オーナーが招待リンクを作る（期限 7 日）・一覧で見る・取り消す。招待リンクを開いた人は、ログイン（またはユーザー登録）してワークスペースに参加し、general に入る | G-4、G-11 |
| FN-05 | メンバー管理 | ワークスペースのメンバーの一覧を見る。オーナーはメンバーをキックできる（キックされた人はワークスペースのすべての会話から外れ、開いている画面からもすぐ追い出される） | G-9、G-18 |
| FN-06 | チャンネル | メンバーが公開・プライベートのチャンネルを作る。公開チャンネルは一覧から探して自分で参加・退出する。プライベートチャンネルは、そのメンバーがワークスペースのメンバーを招待する。チャンネルの削除はオーナーだけができる（general は削除できない） | G-5、G-8、G-13、G-14、G-18 |
| FN-07 | メッセージ | 会話にメッセージ（4,000 文字まで、Markdown 記法）を送る・編集・削除する。送ったメッセージ・編集・削除は、同じ会話を開いているほかの人の画面にすぐ出す（WebSocket）。古いメッセージは上に戻ると 50 件ずつ読み込む | G-5、G-18 |
| FN-08 | スレッド | メッセージにスレッドで返信する。親メッセージには返信の件数と最後の返信の時刻を出し、押すとスレッドのパネルを開く。返信も FN-07 と同じく、送る・編集・削除・リアルタイムで出す | G-5 |
| FN-09 | 画像・動画の添付 | メッセージに画像・動画を 1 通に 4 個まで（画像は 1 個 10MB、動画は 1 個 100MB まで）添付して S3 に保存する。画像は縮小して並べ、押すと拡大する。動画は画面の中で再生する | G-5、G-17 |
| FN-10 | 絵文字リアクション | メッセージに絵文字でリアクションを付ける・外す。絵文字ごとに件数を出し、誰が付けたかを見られる。リアルタイムで出す | G-5 |
| FN-11 | メンション | メッセージに「@ユーザー ID」と書いてメンションする。「@」を入れると、その会話のメンバーの候補を出す。メンションされた人の名前は目立たせて出す | G-5 |
| FN-12 | ダイレクトメッセージ | 同じワークスペースのメンバーを選んで、2 人だけの DM を始める。DM の中の動きはチャンネルと同じ（FN-07〜FN-11） | G-5、G-15 |
| FN-13 | メッセージ検索 | ワークスペースの中で、自分が見られる会話のメッセージ（スレッドの返信を含む）を文字で検索し、新しい順に 20 件ずつ出す。会話・送った人で絞り込める。結果を押すとそのメッセージの位置を開く | G-6 |

## 9. データ要件

扱うデータは、ユーザー・ワークスペース・ワークスペースのメンバー・招待リンク・チャンネル・会話のメンバー（既読の位置を含む）・DM・メッセージ・添付ファイル・リアクション・メンションと、ログインを続けるためのリフレッシュトークンである。上限は、メッセージの本文 4,000 文字、添付は 1 通に 4 個（画像 10MB・動画 100MB）、アバター 5MB とする。保存する個人情報は、ユーザー ID・表示名・アバター・ステータスとパスワード（元に戻せない形）のみとする。

項目・上限・個人情報の詳細は[データ要件定義書](data-requirements.md)に、データの構造（ER 図）はデータ設計書に書く。

## 11. 非機能要件

### 11.1 性能

次の条件で測定する：ユーザー 1,000 人・ワークスペース 100・メッセージ 50 万件（うちスレッドの返信 10 万件）・リアクション 20 万件・添付 2 万件、測定するワークスペースはメンバー 200 人・チャンネル 50・メッセージ 10 万件、同時にログインして WebSocket でつないでいる人 50 人、3.2 の対応環境、下り 10Mbps 以上・上り 30Mbps 以上の回線。同じ操作を繰り返し測り、P95（小さい順に並べて 95% の位置の値）が目標値以内なら合格とする。合否は公開先（AWS）で測った値で決める。

| ID | 内容 | 目標値 |
| --- | --- | --- |
| N-1 | ログインしてワークスペースを選んでから、チャット画面に最新 50 件のメッセージが表示されるまで | 3 秒以内 |
| N-2 | サイドバーで会話を切り替えてから、最新 50 件のメッセージが表示されるまで | 1 秒以内 |
| N-3 | メッセージを送ってから、同じ会話を開いているほかの人の画面に出るまで（編集・削除・リアクション・スレッドの返信も同じ） | 1 秒以内 |
| N-4 | メッセージを送ってから、ほかの人のサイドバーの未読・メンションの表示が変わるまで | 1 秒以内 |
| N-5 | 検索してから、最初の 20 件が表示されるまで | 2 秒以内 |
| N-6 | 画像 4 枚（合計 40MB）のメッセージを送ってから、同じ会話のほかの人の画面に出るまで | 15 秒以内 |
| N-7 | 動画 1 本（100MB）のメッセージを送ってから、同じ会話のほかの人の画面に出るまで | 40 秒以内 |

### 11.2 可用性・データ保全

| ID | 内容 |
| --- | --- |
| N-8 | 稼働時間は AWS の稼働に従う。本アプリ独自の稼働率の目標は設けない。費用を抑えるために止めている間（P-5）は使えない |
| N-9 | WebSocket が切れたときは、画面に「接続が切れました。再接続しています…」と出して自動でつなぎ直す。つなぎ直したら、切れていた間のメッセージ・未読を取り直し、取りこぼしを残さない |
| N-10 | データベースは 1 日 1 回自動でバックアップし、7 日分を残す（RDS の自動バックアップ）。ただし AWS が無料プランの間は、無料プランの上限のため 1 日分だけを残す。失われる可能性があるのは、最後のバックアップ以降の変更のみ |
| N-11 | S3 の添付は、メッセージを削除したとき、編集で添付を外したとき、チャンネルを削除したとき、アップロードしたが送らずに捨てたときにだけ消す。アバターは、変えたとき・外したときに前のものを消す。それ以外で消えないようにする |

### 11.3 セキュリティ

| ID | 内容 |
| --- | --- |
| N-12 | 公開時の通信はすべて HTTPS（暗号化）で行う。WebSocket も暗号化（wss）する |
| N-13 | ログインしていない状態では、データの読み書きを一切できない（招待リンクの画面のワークスペース名を除く）。WebSocket も、ログインしていなければつなげない |
| N-14 | 3.1 の「見られる範囲」の外のデータは、API・WebSocket・検索の結果・添付の署名付き URL のどれからも取れないようにする。とくに、入っていないワークスペース、入っていないプライベートチャンネル、ほかの人の DM のメッセージと添付。画面だけでなくサーバー側でも確かめる |
| N-15 | キックされた人・チャンネルから外れた人には、その時点からその会話のリアルタイムの通知を送らない |
| N-16 | オーナーだけができる操作（招待リンクの作成と取り消し、キック、チャンネルの削除）は、サーバー側でもオーナーかを確かめる |
| N-17 | 各利用者は、自分のメッセージ・添付・リアクション・プロフィールだけを変更・削除できる。画面だけでなくサーバー側でも確かめる |
| N-18 | パスワードは元に戻せない形（BCrypt）で保存する。そのままの形では保存もログ出力もしない |
| N-19 | 同じユーザー ID で 5 回続けてログインに失敗したら、15 分間そのユーザー ID でログインできないようにする |
| N-20 | 画像・動画を置く S3 は外部から直接読めないようにし、画面には署名付き URL で渡す。有効期限は 1 時間とする（長い動画を見ている途中で切れないようにするため） |
| N-21 | メッセージ・チャンネル名・ワークスペース名・プロフィールの文字は、HTML として解釈させずに表示する。Markdown 記法は機能定義書で定めた記法だけを飾りに変え、HTML のタグや「javascript:」で始まるリンクは動かさない（他人の画面でスクリプトを動かさせない） |
| N-22 | 招待リンクの URL には推測できない長い文字列を使う。期限切れ・取り消し済みのリンクでは参加できない |
| N-23 | データベースのパスワード、JWT の署名に使う秘密の値、AWS の認証情報は、ソースコードとリポジトリに置かない |
| N-24 | ログインの状態は JWT で持ち、JavaScript から読めない Cookie（HttpOnly）に入れる。JWT の有効期限は 15 分と短くし、ログインしたままにするためには別のリフレッシュトークン（有効期限 14 日）を使う。ログアウトしたら、リフレッシュトークンをサーバー側で無効にする |
| N-25 | Cookie でログインの状態を持つため、ほかのサイトから利用者になりすまして操作させる攻撃（CSRF）を防ぐ。Cookie に SameSite 属性を付け、データを変える API は CSRF の対策（トークンなど）をしたリクエストだけを受け付ける。WebSocket は、つなぐときに接続元（Origin）が本アプリの画面かを確かめる。やり方は基本設計書で決める |

## 12. リスクと対策

| No | リスク | 影響 | 対策 |
| --- | --- | --- | --- |
| R-1 | AWS の費用が想定を超える（とくに動画の保存と配信） | 費用が発生し続ける | 公開は検収のときだけ行い、使わない間は止める（P-5）。動画の大きさに上限を設ける（FN-09）。AWS Budgets で月 10,000 円を超えそうなときにメールを受け取る |

| R-4 | 招待リンクが意図しない人に渡る | 知らない人がワークスペースに入る | リンクに期限を付け（7 日）、オーナーがいつでも取り消せるようにする（FN-04）。入った人はキックできる（FN-05） |

| R-6 | WebSocket が会社・学校のネットワークやスマートフォンの回線で切れやすい | メッセージがすぐに出ない | 自動でつなぎ直し、切れていた間の分を取り直す（N-9）。画面を開き直せば最新になるようにする |
| R-7 | 公開先で API のコンテナを複数にできない（P-4） | 利用者が増えたときに遅くなる、コンテナの入れ替えの間は使えない | 利用者は数十人のため 1 つで足りる。性能は 11.1 の条件で確かめる |

| R-11 | ブラウザの仕様変更で動きが変わる | 一部の機能が動かなくなる | 保守期間中は不具合として対応する（15 章） |

## 16. 変更管理

承認後に要件を変える場合は、次の手順で行う。

| 手順 | 内容 | 担当 |
| --- | --- | --- |
| 1 | 変更したい内容と理由を、GitHub の Issue に「変更依頼」として書く | 依頼する人（どちらでもよい） |
| 2 | 変更による影響（作業時間、納期、ほかの機能への影響、AWS の費用）を調べ、Issue に書く | 作成者 |
| 3 | 変更するかどうかを決める | 承認者 |
| 4 | 変更する場合は本書・詳細文書（1.3）・機能定義書を書き直し、版数を上げて改訂履歴に記録し、再度承認を受ける | 作成者・承認者 |

版数の上げ方：承認までは 0.1 ずつ上げ（例：0.1 → 0.2）、承認したら 1.0 とする。承認後は、文言の修正のみは 0.1 上げる（例：1.0 → 1.1）。機能の追加・削除は 1.0 上げる（例：1.1 → 2.0）。

詳細文書を変えた場合は、その文書の版数を上げて改訂履歴に記録する。あわせて本書の版数も上げ、改訂履歴に「どの詳細文書を何版にしたか」を記録する。承認は本書で行うため、本書の版数が要件定義書全体の版数となる。
