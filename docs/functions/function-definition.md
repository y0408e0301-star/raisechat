## 1. 本書について

### 1.1 目的

要件定義書 8 章の機能一覧にある機能ごとに、「利用者が何をできるか（機能要件）」と「そのためにアプリが何をするか（処理・入力の確認・API・リアルタイムの通知・データ・エラー）」を 1 つの文書にまとめる。1 つの機能を作るときに、その機能の文書を読めば作れるようにする。

## 2. 共通の決まり（画面）

- 用語（トリム、文字数、会話、未読など）は要件定義書 5 章のとおり
- 「見られる」は、要件定義書 3.1 の「見られる範囲」のとおりである。見られないものは、画面に出さないだけでなく API も返さない（N-14）
- リアクション・参加・退出・削除・保存に失敗したときは、画面をその操作の前の状態に戻して M-49 を出す
- インターネットに接続できないことに気づいたら M-50 を出し、接続が戻ったら消す。WebSocket が切れたときは M-37 を出す（4.4）
- API が 401 を返した（JWT の期限が切れた）ときは、画面は利用者に知らせずに POST /api/auth/refresh で JWT を取り直し、元の操作を 1 回だけやり直す。取り直しにも失敗した（ログインの期限が切れていた）ときは、M-8 を出して G-1 に移す（FN-01 A-8）
- 日時は、今日なら「10:15」、昨日なら「昨日 10:15」、それより前は「11月8日 10:15」、去年より前は「2025年11月8日」のように出す。メッセージに重ねると（スマートフォンでは長押しで）、年月日と秒まで出す
- 表示名の横には、ステータスの絵文字があれば出す（FN-02）。アバターがない人は、表示名の頭文字を丸の中に出す
- ワークスペースの中の画面（G-5〜G-9・G-11）は、そのワークスペースのメンバーでないと開けない。開いた場合は M-13 を出して G-3 に移す

## 3. 共通の決まり（API）

### 3.1 基本

| 項目 | 決まり |
| --- | --- |
| URL | すべて /api で始める。画面の URL（/w/1/c/2 など）と分ける。WebSocket は /ws |
| 形式 | 入力・出力とも JSON（UTF-8）。アバターを送るときだけ multipart/form-data。添付は S3 に直接送る（FN-09） |
| ID | 数値（bigint）。JavaScript で扱える範囲（2 の 53 乗未満）に収まる |
| ユーザーの指定 | URL ではユーザー ID（username）で指定する。大文字・小文字は区別しない |
| 日時 | ISO 8601 形式の UTC（例：2026-11-10T06:30:00Z）。画面で日本時間に直す |
| 文字列 | サーバー側でもトリムし、改行を LF にそろえてから文字数をコードポイントで数えて確かめる（画面の確認だけに頼らない） |
| 権限の確かめ | ワークスペース・会話・メッセージを扱う API は、毎回、ログインした人がそのワークスペースのメンバーか、その会話を見られるかをデータベースで確かめる（N-14）。見られないものは、あるかどうかを教えないため 404 を返す |
| 変更の通知 | データを変える API は、成功したら、コミットの後に 4 章のリアルタイムの通知を送る。通知は API の応答とは別に届くため、画面は自分の操作の結果を API の応答で反映し、同じ内容の通知が後から来ても二重に出さない（4.3） |

### 3.2 ログイン（JWT 認証）と CSRF 対策

ログインの状態はサーバーに覚えさせず（セッションを使わない）、JWT で確かめる（N-24）。流れは FN-01 の 3 章のとおり。

| 項目 | 決まり |
| --- | --- |
| アクセストークン | JWT。署名は HS256（秘密の値は Parameter Store。N-23）。中身は sub（ユーザーの ID）・username・iat（発行時刻）・exp（期限）。有効期限 15 分 |
| リフレッシュトークン | 推測できない 32 バイトの乱数を文字列にしたもの（JWT ではない）。有効期限 14 日。データベースには SHA-256 のハッシュだけを保存する |
| 渡し方 | どちらも Cookie（HttpOnly・SameSite=Lax、公開時は Secure）で渡す。アクセストークンは `access_token`（Path=/、/api と /ws の両方で使うため）、リフレッシュトークンは `refresh_token`（Path=/api/auth）。画面の JavaScript からは読めない |
| 確かめ方 | Spring Security の OAuth2 Resource Server の JWT の確認を使い、Cookie の access_token を読む。署名・期限が正しければ、ログイン済みにする |
| ログインしたままにする | アクセストークンの期限が切れたら、POST /api/auth/refresh で両方を新しくする。リフレッシュトークンは使うたびに新しいものに替える |
| ログアウト | リフレッシュトークンをデータベースで無効にし、両方の Cookie を消す。そのブラウザの WebSocket も切る |
| CSRF | Cookie（XSRF-TOKEN）に入れたトークンを、画面が X-XSRF-TOKEN ヘッダーで送り返す。GET 以外のすべての API で確かめる。トークンを新しくするのはログイン・登録のときだけ（N-25） |
| ログインがいらない API | POST /api/auth/signup、POST /api/auth/login、POST /api/auth/refresh、GET /api/auth/username-availability、GET /api/invites/{招待の文字列}（ワークスペースの名前だけを返す。access_token の Cookie があればその人として扱い、オーナー・人数も返す。FN-04）だけ。それ以外はアクセストークンがなければ 401 |

### 3.3 エラーの形

エラーのときは、HTTP ステータスと次の JSON を返す。画面は message をそのまま出し、field があればその入力欄の下に出す。

```json
{
  "code": "CHANNEL_NAME_TAKEN",
  "message": "この名前のチャンネルはすでにあります。",
  "field": "name"
}
```

| HTTP ステータス | 使うとき |
| --- | --- |
| 400 | 入力が条件に合わない（code は各機能定義書の 9 章）。画面を通さずに送られた入力（JSON が読めない、画面では入力できない長さなど）は、code を BAD_REQUEST、message を「入力が正しくありません。」にする |
| 401 | ログインしていない（UNAUTHENTICATED）、アクセストークンの期限切れ（TOKEN_EXPIRED）、リフレッシュトークンが使えない（REFRESH_FAILED） |
| 403 | 見られるが、その操作の権限がない（オーナーだけの操作、他人のメッセージの編集、参加していない公開チャンネルへの送信など）、CSRF トークンが合わない |
| 404 | ワークスペース・会話・メッセージ・ユーザーなどが存在しない、または見られない |
| 409 | 重複・状態の食い違い（使われているユーザー ID、同じ名前のチャンネル、すでにある DM など） |
| 410 | 期限切れ・取り消し済みの招待リンク（FN-04） |
| 413 | アバター・添付が大きすぎる |
| 423 | ログインの失敗が続いて、ログインできない（FN-01 A-7） |
| 500 | サーバーの中の失敗（S3・データベースの障害など）。message は M-49 か機能ごとのもの |

### 3.4 一覧の読み込み（ページング）

| 項目 | 決まり |
| --- | --- |
| 方法 | カーソル方式。前回の出力の nextCursor を、次の入力の cursor にそのまま渡す。最後まで読んだら nextCursor は null |
| 件数 | メッセージとスレッドの返信は 50 件、検索・メンションの一覧は 20 件、メンバー・チャンネル・招待リンクの一覧は 50 件 |
| カーソルの中身 | 新しい順・古い順の一覧は「最後に出した行の ID」、名前順の一覧は「最後に出した行の名前と ID」を文字列にしたもの。画面はカーソルの中身を読まない |
| 例外 | 会話のメッセージは、上（古い方）にも下（新しい方）にも読めるように、before・after・around で指定する（FN-07 6 章） |

一覧を返す API の出力は、すべて次の形にする。

```json
{
  "items": [ … ],
  "nextCursor": "1234"
}
```

### 3.5 よく使う出力の形

#### ユーザー（UserSummary）

```json
{
  "username": "taro_y",
  "displayName": "たろう",
  "avatarUrl": "https://…（署名付き URL。ないときは null）",
  "statusEmoji": "🏖",
  "statusText": "休暇中"
}
```

statusEmoji・statusText は、ステータスがないか、消す日時を過ぎていれば null（FN-02）。

#### 会話（ConversationSummary）

サイドバーの 1 行に出す情報である。

```json
{
  "id": 12,
  "workspaceId": 3,
  "type": "CHANNEL",
  "name": "旅行の計画",
  "visibility": "PUBLIC",
  "general": false,
  "dmPartner": null,
  "joined": true,
  "hasUnread": true,
  "unreadCount": 5,
  "mentionCount": 1,
  "canPost": true
}
```

- type は CHANNEL か DM。visibility は PUBLIC か PRIVATE（DM では null）
- DM では name は null で、dmPartner に相手の UserSummary を入れる
- joined はチャンネルのメンバーか（DM は常に true）。unreadCount・hasUnread は、メンバーでないときは 0・false
- canPost は、いまメッセージを送れるか（公開チャンネルで参加していない、DM の相手がワークスペースを抜けた、ときは false）

#### メッセージ（MessageView）

```json
{
  "id": 1234,
  "conversationId": 12,
  "parentId": null,
  "author": { "username": "taro_y", "displayName": "たろう", "avatarUrl": null, "statusEmoji": null, "statusText": null },
  "body": "**土曜**の集合は駅前で @hana",
  "mentions": ["hana"],
  "attachments": [
    { "id": 77, "kind": "IMAGE", "contentType": "image/png", "fileName": "photo.png", "size": 204800,
      "width": 1600, "height": 1200, "url": "https://…（署名付き URL）", "thumbnailUrl": "https://…",
      "downloadUrl": "https://…（元のファイル名で保存させる）", "expiresAt": "2026-11-10T07:30:00Z" }
  ],
  "reactions": [
    { "emoji": "👍", "count": 3, "reactedByMe": true,
      "users": [ { "username": "hana", "displayName": "はな" }, { "username": "jiro", "displayName": "じろう" }, { "username": "taro_y", "displayName": "たろう" } ] }
  ],
  "replyCount": 2,
  "lastReplyAt": "2026-11-10T01:07:00Z",
  "replyUsers": [ { "username": "hana", "displayName": "はな", "avatarUrl": null, "statusEmoji": null, "statusText": null } ],
  "createdAt": "2026-11-10T01:02:00Z",
  "editedAt": null,
  "deleted": false,
  "mine": true,
  "canDelete": true
}
```

- body は Markdown 記法のまま返す。飾りに変えるのは画面で行う（FN-07 5 章）
- mentions は、本文のメンションのうち記録したもの（FN-11）の username。画面はこれに含まれる「@ユーザー ID」だけを目立たせる
- reactions は、絵文字が最初に付けられた順。reactions.users は、絵文字を付けた人の username と表示名を、付けた順に最大 20 人まで返す（重ねたときに出す。FN-10）
- deleted が true のとき（スレッドの返信がある親メッセージを削除したとき。FN-07 MS-11）は、body は空、attachments・reactions は空の並びにする
- canDelete は、自分のメッセージか、自分がそのワークスペースのオーナーのときに true
- replyUsers は、返信のある親メッセージの、最後に返信した人から 3 人（画面設計書 2.9 の返信した人のアバター）
- スレッドの返信（parentId があるもの）では、replyCount は 0、lastReplyAt は null、replyUsers は空の並び

## 4. 共通の決まり（リアルタイムの通知）

### 4.1 つなぎ方

| 項目 | 決まり |
| --- | --- |
| 方式 | WebSocket の上で STOMP（メッセージの宛先と購読を決める取り決め）を使う。画面からサーバーへは購読（SUBSCRIBE）だけを送り、メッセージの送信などは API（HTTP）で行う |
| URL | /ws（公開時は wss://〜/ws。N-12） |
| ログインの確かめ | つなぐときに Cookie の access_token を確かめる。ないか正しくなければつながない（N-13。つなぎ始めの HTTP が 401 になる）。つなぐときに Origin が本アプリの画面の URL（環境変数 WEB_ORIGIN）かを確かめ、違えば 403 にする（N-25）。STOMP の CONNECT での CSRF のトークンの確かめは行わない（Origin の確かめで防ぐ） |
| つなぐ時期 | ログインしている間、画面を開いている間はつなぎ続ける。ログアウトしたら切る |
| JWT の期限 | サーバーは、つないだときの JWT の期限が来たら、番号 4001（TOKEN_EXPIRED）を付けて接続を切る。画面は 3.2 のとおり JWT を取り直してつなぎ直す。この切れ方では M-37 を出さない |
| 生きているかの確かめ | 画面とサーバーは 20 秒ごとに合図（ハートビート）を送り合い、届かなくなったら切れたとみなす |

### 4.2 購読する宛先

| 宛先 | 届くもの | 購読できる人 |
| --- | --- | --- |
| /user/queue/events | その人あての通知（サイドバーの未読・メンション、会話への参加・退出・削除、ワークスペースから外れた、ブラウザの通知に使う情報など） | 本人だけ（つないだ人に自動で決まる） |
| /topic/conversations/{会話の ID} | その会話のメッセージ・スレッドの返信の送信・編集・削除、リアクション | その会話を見られる人。購読のときにサーバーが確かめ、見られなければ断る（STOMP の決まりで、ERROR を送って接続を切る。画面はつなぎ直し、4.4 の取り直しで見られないことが分かる） |

この 2 つ以外の宛先の購読と、画面からの SEND（STOMP のメッセージの送信）は断る。

画面は、/user/queue/events をつないでいる間ずっと購読し、/topic/conversations/{id} は G-5 でいま開いている会話（と、開いているスレッドの会話）だけを購読する。会話を移ったら前の会話の購読をやめる。

### 4.3 通知の形と種類

通知はすべて次の形の JSON にする。

```json
{
  "type": "message.created",
  "workspaceId": 3,
  "conversationId": 12,
  "payload": { … },
  "sentAt": "2026-11-10T01:02:00Z"
}
```

| type | 宛先 | payload | 送るとき | 定めている機能 |
| --- | --- | --- | --- | --- |
| message.created | 会話 | MessageView | メッセージ・スレッドの返信を送った | FN-07、FN-08 |
| message.updated | 会話 | MessageView | 編集した、親メッセージの返信の件数が変わった、親メッセージを削除して「削除されました」にした | FN-07、FN-08 |
| message.deleted | 会話 | `{"id","parentId"}` | メッセージ・返信をデータごと消した | FN-07、FN-08 |
| reaction.updated | 会話 | `{"messageId","reactions"}`（reactions は MessageView と同じ形。reactedByMe は受け取った画面で直す） | リアクションを付けた・外した | FN-10 |
| conversation.updated | 本人 | ConversationSummary | 未読・メンションの件数が変わった、会話に参加した・招待された、DM にメッセージが送られた、DM の相手がワークスペースを抜けた・戻った（canPost） | FN-05、FN-06、FN-12、FN-14 |
| conversation.removed | 本人 | `{"conversationId","reason"}`（reason は LEFT・DELETED） | 会話から抜けた、チャンネルが削除された | FN-06 |
| workspace.updated | 本人 | `{"workspaceId","hasUnread","mentionCount"}` | 自分のワークスペースの未読・メンションの有無が変わった（G-3 の印） | FN-14 |
| workspace.removed | 本人 | `{"workspaceId","name","reason"}`（reason は KICKED・LEFT・DELETED） | キックされた、退出した、ワークスペースが削除された | FN-03、FN-05 |
| notify | 本人 | `{"kind","message","conversationName"}`（kind は MENTION・DM、message は MessageView） | メンションされた、DM が届いた（ブラウザの通知とメンションの一覧に使う） | FN-11、FN-14 |

- 自分の操作の通知も、自分の画面に届く（別のブラウザ・タブで開いていても同じ表示にするため）。画面は、メッセージの ID が同じものは 1 つだけ出す
- payload の MessageView は、会話を見ている人みんなに同じものを送るので、見る人によって変わる mine・canDelete は false にして送る。画面は、送った人が自分なら mine を true にし、canDelete は「削除されていない、かつ（自分のもの、または自分がオーナー）」で求め直す
- 通知の形は、サーバーが実際に送った JSON を docs/api/realtime-events.json に書き出し、画面のテストがそれを読めることを確かめる（基本設計書 2.1）
- 通知は、送ったときにつながっていない人には届かない。届かなかった分は、つなぎ直したときに API で取り直す（4.4）

### 4.4 切れたとき・つなぎ直したとき

| 場面 | 画面がすること |
| --- | --- |
| 切れた（4.1 の JWT の期限の場合を除く） | M-37 を出し、1 秒・2 秒・4 秒…（最大 30 秒）と間を空けてつなぎ直す。つなぎ直す前に GET /api/auth/me を呼び、JWT の期限が切れていれば取り直す（取り直せなければ M-8 を出して G-1 に移す）。インターネットに接続できないときは、M-37 の代わりに M-50 を出す（画面設計書 2.20） |
| つなぎ直せた | M-37 を消し、購読し直す。そのあと、サイドバー（GET /api/workspaces/{ws}/conversations）、開いている会話（GET /api/conversations/{id} と最新の 50 件）、開いているスレッドを取り直す。新しいメッセージと、編集・削除・リアクションの取りこぼしをなくすため、開いている会話の、画面に出しているメッセージは取り直した最新の 50 件で置き換える（切れている間に 50 件より多く届いていたら、上に戻ると前を読む） |
| つなぎ直しても、見られなくなった会話・ワークスペースだった | 取り直しの API が 404 を返したら、画面一覧 2 章の「見られない会話の URL を開いた場合」と同じにする |

### 4.5 見られなくなった人への通知の止め方

キック・退出・チャンネルからの退出・チャンネルの削除・ワークスペースの削除で、会話を見られなくなった人には、その時点から、その会話の通知を送らない（N-15）。そのために、サーバーは次のことを行う。

1. コミットの後、本人に conversation.removed または workspace.removed を送る
2. その人の、見られなくなった会話の /topic/conversations/{id} の購読をサーバー側で取り消す。取り消せないときは、その人の WebSocket の接続をすべて切る（画面はつなぎ直し、見られない会話は購読できない）
